errors: Errors are sorted into network, server, validation, permission and unexpected; each says what happened in plain words and offers retry, correction or a way out.
interrupted_external_flow: payments: When the person leaves for The user leaves the app for the provider's own step and returns with a result; the app never handles card or account secrets itself. and returns without finishing, the app shows where things stand and lets them continue or cancel. If the app is closed or killed during the provider's step, the next open asks the provider for the status of the last attempt and shows the result; nothing is charged twice.
loading: Every wait that lasts more than a moment shows that content is coming; a wait that passes the timeout becomes an error with retry.
notifications: Notifications are asked for in context, open the screen they are about, and do nothing sensitive before the user signs in. Opening a notification goes to the screen it is about when the signed-in role may see it.
offline: Without a network the last saved data is shown as stale, actions that need the network say so, and queued actions are sent in order when the network returns. Data shown while offline is marked as saved earlier; actions that need the network say so and are queued only where a screen says they may be.
pending_timeouts: payments: A pending result is waited for as stated: A pending result is waited for a limited time, then shown as unknown with a way to check again or contact support; the limit is on the confirm list. When the wait ends the person sees that the result is unknown and can check again.
session: A session is kept in secure device storage, renewed quietly before it expires, and an expired session sends the user to sign in again with their place and unsent work kept. Roles can differ: Members, Studio owner, Studio staff, Instructors. A session that expires while work is unsent keeps that work and asks the person to sign in again.
