# Global rules (commit policy, repository layout, always)

Source: the "GLOBAL RULES" block of build prompt 02 (`docs/compass/build-prompts/02-compass-ai-interview-prompt.md`; its canonical home was `prompts/00-global-rules.md`, which is not in this repository). These rules apply first and override anything in a task prompt that conflicts with them, except where the owner has recorded a local override at the end of this page.

## A. Commit policy (nothing missed, everything revertible)

1. **Start (medium, major and overhaul tasks; a small task needs no checkpoint).** Size guide: *small* is a typo, a one-file fix, a doc edit or a config tweak; *medium or major* is several files or more than one package, a behavior change, a call spec, schema, data files, migration or dependency, or work that takes more than one sitting; *overhaul* is rule 11. When unsure take the larger size. Then: `git status`; commit any pre-existing uncommitted changes separately as `chore(wip): checkpoint existing changes before <task>` (never discard, never mix); note the branch and hash; create the tag `pre/<task>-<yyyymmdd-hhmm>`. If the tree is already clean, the current commit is the checkpoint: just tag it. This is the whole point: if the work goes wrong, one tag gets you back (rule 10).
2. **Branches.** Work on a branch `feat/<agent>-<task>` (one branch per parallel agent, per the repo worktree rule). Merge to `main` only when green, with `git merge --no-ff` (no squash, no rebase of shared history), so the whole task reverts with `git revert -m 1 <merge-hash>`.
3. **Small atomic commits**, one reason each. Commit at least every 15 to 20 minutes, before any risky step (migration, large move, deletion, dependency change) and before any time or usage limit ends. No uncommitted work at the end of a session; `git status` clean.
4. **Every commit leaves its area green.** Moves use `git mv` in a commit that contains only moves plus the config edits needed to stay green (verify with `git diff -M --stat`). Do not mix formatting, refactor, behavior and docs. Tests go with their code. Migrations, generated files, and decision, ADR and PROGRESS updates get their own commits.
5. **Message.** `type(scope): imperative summary` (72 characters or fewer), a blank line, a body (what and why, decisions, tests run with counts, risks, how to revert if non-trivial), then the footer `Task: <prompt id>`, `Phase: <n>`, `Refs: D-nnn, ADR-00nn`, followed by the repository's trailer convention (`Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`). Types: `feat fix refactor test docs build chore perf revert wip`. Scope: the agent or package.
6. **Tags.** After each green phase an annotated tag `<agent>/<task>-p<n>` (for example `compass/ai-interview-p3`) with a one-paragraph description; `pre/<what>-<yyyymmdd-hhmm>` before risky steps. Never move or delete tags, branches or other agents' files without the owner's yes.
7. **Never:** force-push; `git reset --hard`, `git checkout .`, `git clean -fd` on uncommitted or unbacked-up work; amend or rewrite pushed commits; commit secrets, caches, `.venv`, `node_modules`, data directories or large binaries (cassettes are fine after the secret scan); commit conflict markers (`git grep '^<<<<<<<'` before every merge commit).
8. **Remote.** Run `git remote -v`. If a GitHub remote exists, push the task branch and tags after every phase and at the end with plain `git push` (never `--force`); do not push to `main` directly unless the owner said so; no pull requests unless asked. If there is no remote, commit locally, say so in the report, and never create or change remotes. *(See the local override below.)*
9. **Each commit must be revertible alone** (`git revert <hash>`); migrations get working downgrades.
10. **Report.** Branch and tag names; `git log --oneline` for the task; push status; working-tree status; and the exact revert commands for the last commit, for the whole task (`git revert -m 1 <merge-hash>`), and for returning to a tag without losing history (`git switch -c recover/<name> <tag>`).
11. **Complete overhaul (owner's order, 2026-11-11).** Replacing or rewriting a subsystem, a large move or rename, or any change that makes current work obsolete is not done on the branch you are on. Do the checkpoint of rule 1, then **stop before changing anything** and give the owner the plan: what is replaced, why, what stays, how to go back. Only after the owner's yes: create a new branch `feat/<area>-<overhaul>` from the checkpoint tag and work there with rules 3 to 9. Never overhaul on `main` or on another agent's branch; merge into `main` only with the owner's yes, with `--no-ff`. A subagent that finds its task is an overhaul stops and reports; the lead asks the owner. This is the one case where an agent asks the owner a question (CLAUDE.md rule 12).
12. **Scope of this policy.** It is a safety net for traceability and revert, and nothing else. It does not tell an AI how to plan, reason, order its work, use tools or use subagents; none of that is restricted here.

## B. Repository layout

- `agents/<name>/`: one self-contained folder per agent: LLM prompt templates, structured call specs, schemas, examples, mocks, catalogs and data, engine logic, store, API router and `create_app()`, tests, evals, README, and a copy of its build prompts under `docs/`. Package names stay `mde_<agent>`.
- `apps/web/`: the **global front end** for all agents (today a static HTML, CSS and vanilla-JS test console, later React), **never inside an agent folder**. `apps/<other>/`: other apps.
- `packages/*`: shared infrastructure and legacy packages. Legacy agents in `packages/` stay untouched until replaced and retired in a separate task.
- Agents import shared packages only, never each other or any app. The front end never imports agent code and talks to agents only through their HTTP API and the shared JSON Schemas. Each agent exposes `create_app()` and a `router`.
- The uv workspace members include `agents/*` and `apps/*` (a non-Python directory such as `apps/web` is excluded); update import-linter and CI paths when something moves.
- Front end: `apps/web/console/` (shell with an agent switcher, `shared/` tokens and components, `agents/<name>/` screens), `apps/web/app/` reserved for React, `apps/web/tests/` for UI smoke tests. Static files are served by an agent's dev server from `MDE_WEB_DIR` (default `apps/web/console`).

## C. Always

Log decisions and ADRs; update `PROGRESS.md`; respect the repository's rules on secrets, live spend (the owner's caps are hard limits), memory (one test suite at a time) and the operating system.
