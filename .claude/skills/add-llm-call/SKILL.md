# Add or change an LLM call

Every LLM call is a versioned `CallSpec` run by the gateway. No prompt text lives in engines. Package page: [docs/packages/prompts.md](../../../docs/packages/prompts.md); generated table of all specs: [docs/prompts/prompt-catalog.md](../../../docs/prompts/prompt-catalog.md).

1. **IO models.** Input and output models live in `mde_contracts` (`calls.py`) and the call id is listed with its models in `mde_contracts.registry.CALL_IO`. If they do not exist or need a field, do not edit the package: ask the lead in your report (an additive change, ADR 0011). Output models must convert to OpenAI strict schema (no open objects, no free-form JSON, depth <= 5; slot values as `value_text | value_list | value_bool`).
2. **Folder.** Create `packages/prompts/src/mde_prompts/calls/<folder>/` where `<folder>` is `mde_contracts.registry.call_folder(call_id)` (for example `c7_extract` for `C7.extract`), containing `__init__.py`, `spec.py`, `system.jinja`, `user.jinja`, `mock.py` and `fixtures/`.
3. **Spec.** In `spec.py` build `SPEC: CallSpec[I, O]`: `id`, `version=1`, `input_model`, `output_model` (None only for `S1.web_search`), the two templates and `template_root=Path(__file__).parent`, `route` (fast, standard or deep), `reasoning_effort` (what the catalog uses today: C1, C2, C3, C5, C6, C7, C13 and S1 low; C8, C9a/b/c, C10, C11, C12, C14 medium), `max_output_tokens` (always set; reasoning tokens count), `untrusted_inputs` (fields with web or upload text), `cacheable`, `repair`, `fallback` (a name the owning engine registers) and `mock_handler` (a dotted path `pkg.module:function`). A spec with `untrusted_inputs` must have no tools: `CallSpec` refuses the combination at construction and the gateway refuses it again.
4. **Templates.** One job per call; short system prompt; two or three examples for C1 and C14 (including Hindi and Hinglish); the extraction rule "copy only what the content states; null when unknown; never infer"; the proposals rule "only additions or edits justified by the Brief or Research Note; reference baseline ids". Pass only the context the call needs. Appendix A of `docs/implementation/BRIEF.md` is the writing guide.
5. **Mock handler.** `mock.py` has `def handle(input: I) -> O | FreeTextResult` (only S1 returns free text): deterministic, schema-valid output derived from the input, so the product runs offline with no key. Put golden cases in `fixtures/` next to it.
6. **No registry edit.** `mde_prompts.registry` finds `calls/<folder>/spec.py` by convention (D-016) and checks that the spec's models are the ones in `CALL_IO`. Register the deterministic fallback by name in the owning engine (`FALLBACKS` in discovery, research and the builder); an engine refuses a spec whose fallback it does not register.
7. **Tests** in `packages/prompts/tests/test_calls_<id>.py` (copy a neighbour): mock output validates, strict-schema conversion works, templates render with the fixtures, untrusted-plus-tools is rejected, the fallback exists. Run `uv run pytest packages/prompts`, then the owning engine's tests (`packages/discovery`, `packages/research` or `packages/spec-builder`).
8. **Catalog and docs.** `uv run python scripts/gen_prompt_catalog.py` (writes `docs/prompts/prompt-catalog.md`); update the owning package page in `docs/packages/`.
9. **Changing an existing call:** bump `version`, update fixtures, rerun the catalog. A new version or a changed prompt, model, tool set, effort or schema makes the old cassettes stale (a replay miss): flag the re-recording to the lead (live batches are for the lead or the user, never for you).
